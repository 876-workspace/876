## Changes

- `packages/billing-ui/src/panels/invoice-document-panel.tsx`: shared printable invoice rendering.
- `packages/billing-ui/src/document/invoice-document-data.ts`: host adapter from the full invoice resource to already-formatted panel props.
- `packages/billing-ui/src/panels/invoice-document-panel.test.tsx`: 14 panel cases covering optional blocks, line service periods, an empty table, and string-only money presentation.
- `packages/billing-ui/package.json`: exports the panel and adapter subpaths.
- `apps/billing/src/app/(app)/(sales)/invoices/[invoiceId]/page.tsx`: renders the shared panel. The adapter boundary uses `as unknown as InvoiceDetail` because Billing's existing `resolveInvoice` is a legacy passthrough record while the typed client now validates the actual retrieve shape.
- `apps/invoice/src/app/(app)/invoices/[invoiceId]/page.tsx`: retrieves the full invoice through `getBilling(context.orgId)` and renders the shared panel, preserving its guard, permissions, actions, work widget context, and print layout.
- `apps/invoice/src/app/(app)/invoices/_components/invoices-section.tsx`: print-only split-view layout rules.
- `packages/billing/src/{resources/invoices.ts,types/index.ts,types/invoice.ts,types/invoice.schema.ts}`: typed full invoice retrieve response and line-update contract.
- `apps/billing-api/src/modules/documents/schemas/invoice.ts`: permits a non-empty replacement `lines` array by reusing `DocumentLineCreateSchema`.
- `apps/billing-api/src/modules/documents/repositories/invoices/update.ts`: permits replacements only for DRAFT invoices; uses `buildDocumentLines` and `calculateDocumentTotals`, then atomically replaces lines and totals.
- `apps/billing/src/types/invoice.ts` and `apps/invoice/src/lib/client/documents.ts`: update inputs accept lines.
- Both invoice edit-form/page pairs: full-width forms and DRAFT line-item editor using the existing `DocumentLineItemsEditor`; Invoice edit now retrieves directly instead of list-and-find.

## Decisions and gaps

Phase B intentionally accepts only `lines` in addition to the existing header fields. Customer, currency, price list, and document-level adjustments remain creation-time snapshots; changing any of those safely needs distinct lifecycle policy.

Phase C was not completed to the brief’s expected option (a). The two create-form forks diverge substantially in data loading, catalogue pricing, and client transport. I did not begin an unsafe de-fork. The old `invoice-edit-form.tsx` files remain because this partial implementation still uses them. This is a deliberate gap, not a completed Phase C.

The brief premise that the Invoice retrieve result lacked lines was false after the client contract was reconciled: Billing's retrieve repository includes `customer`, `lines`, and late-fee relations.

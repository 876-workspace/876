## Implementation direction

- Implement the plan incrementally on this branch only.
- Reuse canonical `WorkContext` and `WorkTaskLink` semantics. Do not create a third persisted context model.
- Keep host-resource identity separate from browser transport configuration. Do not add route URLs such as `workEndpoint` to a canonical resource reference.
- A host page may supply display metadata, but its BFF must independently authorize the resource. Browser context is never authority.
- Enforce host-resource permission, Work permission, and widget feature entitlement as distinct server-side gates. Tests must exercise each real gate rather than mocking one combined helper and naming it three gates.
- Retrieve or authorize the exact host resource. Do not search only the first page of a list and treat absence as a reliable 404.
- Contextual reads may expose directly linked visible Work without requiring current-user assignment, but must remain organization isolated and must not traverse host databases from Work.
- Personal routes must reject client-supplied authoritative identity or context.
- Contextual Task, Event, and Reminder create behavior must either be implemented consistently where canonical contracts support it or left explicitly incomplete in the tracker. Do not mark partial Task-only work as complete for all three.
- Preserve Phase 3 generation/race guards, stale-success rendering, error containment, and calendar range reuse across scope changes.

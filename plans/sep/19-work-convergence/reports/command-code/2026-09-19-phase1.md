## 3. Migration — written, not run

```
apps/crm-api/prisma/migrations/20260919120000_drop_dead_request_task_tables/migration.sql
```

```sql
-- CRM request tasks and reminders moved to the Work service
-- (docs/architecture/019-work-service-and-productivity-plane.md). Nothing in
-- crm-api reads or writes these tables, so they and their dedicated enums go.
DROP TABLE IF EXISTS "crm_request_tasks";
DROP TABLE IF EXISTS "crm_request_reminders";
DROP TYPE IF EXISTS "TaskStatus";
DROP TYPE IF EXISTS "ReminderStatus";
```

Notes on the SQL:

- Only the `20260827090000_crm_teams_categories_tasks` migration creates these
  tables/enums; the `20260828235000` migration only adds the `priority_id`
  column. No later migration, view, or trigger depends on them, so plain drops
  are sufficient — `CASCADE` was not used.
- `IF EXISTS` was chosen deliberately: dev and production share databases and a
  hand-written destructive migration should not hard-fail if a table was
  already removed out-of-band. The enum drops are not `CASCADE`, so if anything
  unexpected still uses them the migration fails loudly instead of silently
  dropping a live type.
- No `prisma migrate dev`, `migrate deploy`, or any other database command was
  run. The file was not validated against a live Postgres.

## 6. What could not be verified

- **`pnpm --filter @876/crm-api boundaries` does not exist.** `crm-api` has no
  `boundaries` script (only `api`, `billing-api`, `commerce-api`,
  `communications-api`, `couriers-api` and `couriers` do). The command fails
  with `ERR_PNPM_RECURSIVE_RUN_NO_SCRIPT`. The dependency-cruiser boundary check
  was therefore not run for this app. If crm-api is meant to have one, that is a
  pre-existing gap unrelated to this phase.
- **The migration SQL has not been executed or syntax-checked against a live
  database**, by design. `prisma generate` validates the schema, not the
  migration; the SQL was reviewed by hand against the creating migration
  (`20260827090000`) and the later `priority_id` alteration
  (`20260828235000`).
- The brief's final `grep … # expect 0` is not literally met; see §4 for why,
  and for the scoped greps that are zero.

The implementation:

- Digits come from one source: `Intl.NumberFormat(...).resolvedOptions().maximumFractionDigits`. The hand-written `EXPONENTS` table is deleted. Verified equal to that table for every currency it listed (JMD 2, USD 2, JPY 0, KRW 0, BHD 3, JOD 3).
- `Intl.NumberFormat` instances are cached in a module-level `Map`, keyed by uppercased code.
- Preserved behaviours: `null`/`undefined` → `'—'`; missing currency → raw amount string; non-integer/unsafe amount → `` `${CODE} ${amount}` `` (no `minor units` suffix); lowercase codes normalised.
- `majorToMinor` keeps console's validation (non-decimal string, too many fraction digits, unsafe result) and now returns **`bigint`**; the unsafe check is `amount > BigInt(Number.MAX_SAFE_INTEGER)` — no float touches the amount.
- Locale is `en-JM`. This is forced by the contract that could not be edited: `apps/billing/src/lib/billing-format-extended.test.ts` pins `formatMoney(0n, 'USD') === 'US$0.00'` and a `-` for JMD, which only `en-JM` produces; couriers and invoice already used `en-JM`.

## Billing `formatDate` — genuinely different, left alone

`apps/billing/src/lib/format.ts` keeps its own `formatDate` because it differs from `@876/core/timestamps` in three observable ways:

1. **Signature and falsy handling**: billing takes `number | null | undefined` and returns `'—'` for any falsy value (its own test asserts `formatDate(0)` → `'—'`); core takes `number` and would render `0` as the epoch.
2. **Locale/order**: `en-JM` with `{ day, month, year }` renders `'11 Jul 2026'`; core's `en-US` renders `'Jul 11, 2026'`.
3. **Timezone**: billing formats in the runtime's zone; core pins `timeZone: 'UTC'`.

## Behaviour changes to be aware of

- Billing's `null` amount now renders `'—'`, not `'Custom pricing'` (the unit's rule is null/undefined → em dash); coupon/price surfaces that relied on that copy change accordingly.
- The per-call `decimalPlaces` override is gone; the credit-note layout now shows the currency's Intl digits. If tenant-configured `currency.decimalPlaces` is a real policy rather than a stale mirror of ISO precision, that policy currently has no formatter — flagged for the owner.
- Console's locale moves `en-US` → `en-JM`: JMD renders `$1,234.56` instead of `JMD 1,234.56`, USD renders `US$12.34`.
- Billing's unsafe-amount fallback no longer appends `' minor units'`.
- `app-structure.md` already documents `format.ts` as "re-exports `@876/core`, never reimplements"; console's copy now obeys that rule.

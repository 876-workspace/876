# Orchestrator Review and Verification

Date: 2026-09-08

Reviewer: primary agent

## Review outcome

The delegated implementation was not accepted unchanged. The thermo-nuclear
maintainability review found and corrected two architectural issues. No
remaining blocker, high, or medium finding is known after the corrections and
verification below.

## Findings and resolutions

### High — enabled widget IDs included an unrenderable secondary-rail item

- Location: `packages/widgets/src/catalog.ts`, `apps/billing/src/lib/features.ts`
- Problem: the first delegated resolver returned `chat` together with panel
  widgets. Existing Console and Couriers semantics keep Chat separate from
  `enabledWidgetIds`, and `SharedWidgetDock` silently ignored `chat` because it
  has no panel renderer. This duplicated state and weakened the generic ID
  contract.
- Resolution: added the metadata-owned `WidgetSurface` classification. Notepad
  and Console Live Logs are `panel`; Chat is `secondary-rail`.
  `resolveEnabledWidgetIds` now returns only enabled panel widgets, while
  Billing retains its existing Chat evaluation and secondary rail.

### Medium — extending WidgetHost exposed duplicated, incomplete maps

- Location: Console widget list, registration, data, overview, and access UI
- Problem: four exhaustive host-label maps failed to compile after `invoice`
  was added, and a fifth inferred map would have made Console's "all apps"
  calculation stale. Repeating another Invoice label in every file would have
  preserved the maintenance defect.
- Resolution: added canonical `WIDGET_HOST_LABELS` beside
  `WIDGET_HOST_APP_SLUGS` in `@876/widgets` and replaced all Console copies.
  The union, app slugs, and display labels now evolve together.

### Low — unnecessary resolver input mode and non-null assertion

- Location: `packages/widgets/src/catalog.ts`,
  `packages/widgets/src/react/widget-popout.tsx`
- Problem: accepting arrays or sets added an unneeded runtime branch, and the
  width resolver used a non-null assertion immediately after an undefined
  check.
- Resolution: the resolver now takes the repository's actual
  `ReadonlySet<string>` contract only, and panel width narrowing uses a local
  value with no assertion.

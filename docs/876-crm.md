# 876 CRM — running and operating it

Companion to `docs/architecture/023-876-crm.md`, which covers why the service is shaped the way it is.

## Workspaces

| Workspace      | Path              | Port         | Role                                                 |
| -------------- | ----------------- | ------------ | ---------------------------------------------------- |
| `@876/crm-app` | `apps/crm`        | 3007         | Standalone CRM web application                       |
| `@876/crm-api` | `apps/crm-api`    | 4010         | Express CRM data service                             |
| `@876/crm`     | `packages/crm`    | typed client | Bounded typed client & wire contracts                |
| `@876/crm-ui`  | `packages/crm-ui` | shared UI    | Shared record shells, customer cards, timeline views |

Platform app slug: **`876-crm`**.

## Running it

```bash
pnpm dev:crm        # starts CRM app, CRM API, core API, Billing API, and Work API
pnpm dev:crm:api    # starts CRM API, Billing API, and Work API in parallel
```

`crm-api` is also started by `pnpm dev:console`, as Console renders the CRM operator workspace.

## Environment

`apps/crm-api`:

| Variable                           | Required    | Purpose                                                                       |
| ---------------------------------- | ----------- | ----------------------------------------------------------------------------- |
| `CRM_DATABASE_URL`                 | yes         | Neon **pooled** connection URL                                                |
| `CRM_DIRECT_DATABASE_URL`          | yes         | Neon **direct** endpoint, migrations only                                     |
| `CRM_INTERNAL_KEY`                 | yes, secret | Every `/v1` route requires it as `x-internal-key`; empty rejects all requests |
| `BILLING_API_URL`                  | yes         | Origin for `@876/billing/integration` calls                                   |
| `WORK_API_URL`                     | yes         | Origin for `@876/work` shared productivity calls                              |
| `PORT`, `ENVIRONMENT`, `LOG_LEVEL` | no          | Defaults in code (port defaults to 4010)                                      |

`apps/crm`:

| Variable                 | Required    | Purpose                                                              |
| ------------------------ | ----------- | -------------------------------------------------------------------- |
| `SESSION_COOKIE_SECRET`  | yes, secret | **Must equal `apps/api`'s value byte for byte**                      |
| `CRM_API_876_KEY`        | yes, secret | App platform key (`876_app_secret_...`) presented as `X-876-API-Key` |
| `CRM_INTERNAL_KEY`       | yes, secret | Server-to-server calls to `apps/crm-api`                             |
| `API_INTERNAL_KEY`       | yes, secret | Privileged platform reads, server-only                               |
| `CRM_API_URL`, `API_URL` | yes         | Service origins                                                      |
| `WORK_API_URL`           | yes         | Service origin for 876 Work                                          |
| `NEXT_PUBLIC_CRM_URL`    | yes         | App origin (`http://localhost:3007`)                                 |
| `NEXT_PUBLIC_APP_URL`    | yes         | Consumer app origin (`http://localhost:3000`)                        |

A mismatched `SESSION_COOKIE_SECRET` does not error loudly: every visitor is treated as signed out and bounced to `/login`. Run `pnpm check:session-secret` to verify parity.

## Migrations

Migrations use the **direct** endpoint:

```bash
pnpm --filter @876/crm-api db:deploy    # apply committed migrations
pnpm --filter @876/crm-api db:generate  # regenerate the Prisma client
```

## Caller Tiers

| Caller                                            | Entrypoint           | Credential                                           |
| ------------------------------------------------- | -------------------- | ---------------------------------------------------- |
| Console, administering any organization           | `@876/crm/operator`  | internal key, server-only                            |
| The standalone app, acting for a signed-in member | `@876/crm/service`   | internal key, server-only, org resolved from session |
| Pure wire contracts and schemas                   | `@876/crm/contracts` | types only, no runtime credential                    |

## Architectural Invariants

1. **Financial Customer Data belongs in Billing:** CRM never stores credit card details, ledger balances, invoices, or billing addresses. It references `billingCustomerId` and queries `@876/billing/integration`.
2. **Productivity Primitives belong in Work:** Tasks, reminders, and calendar events are stored in `apps/work-api` with context `{ service: 'crm', resource: 'request', id: '...' }`.
3. **Tenant Priorities & Categories are Materialized:** The platform publishes standard defaults via the `application/876-crm` provisioning catalog; organizations customize their own local priorities and categories without breaking platform updates.
4. **No Direct Browser Access:** The browser never calls `apps/crm-api` directly. Mutations go through same-origin `/api/...` routes in `apps/crm` that call the server-side `$876` facade.
